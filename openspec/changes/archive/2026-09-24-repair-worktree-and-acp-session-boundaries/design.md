## Context

当前 `createSession.workspaceId` 同时承担运行目录和项目归属：新工作树首发改写它后，任务索引按工作树路径分组，侧栏又以目录末段命名，形成多个同名项目。ACP 投影只在整轮结束时关闭思考段，只将顶层 `{error}` 视为失败；Agent 返回 `refusal` 与错误元数据时变成成功空白。ACP SDK 支持原生 `modes` 和 `session/set_mode`，当前连接只投影模型与思考等级。详见 proposal 和两个 delta spec。

## Goals / Non-Goals

**Goals:** 保持任务运行路径与项目归属独立且持久；按原生 ACP 模式做首轮前选择与确认；准确投影失败与思考段终态。

**Non-Goals:** 不对 ACP 子进程工具建立操作系统沙箱；不把内置 Agent 的 yolo/build 值转换成 ACP mode ID；不承诺修复第三方服务的网络故障。

## Decisions

1. **任务身份仍按运行工作区隔离。** `workspacePath` 和 `workspaceIdentity` 保持会话的实际执行位置及索引主键。源项目路径随工作树 tab 持久化，ACP 任务创建时写入任务元数据；CLI 任务在归档清理前把经过托管标记与 Git 双重核验的归属写入任务元数据，后续状态同步保留已确定的值。活动工作树即使关闭 tab，也由托管列表作为任务查询目录挂在原项目下；不凭目录名推断。
2. **项目侧栏只改变分组投影。** 各工作树继续按自身路径查询任务和执行命令，侧栏把属于同一源项目的任务投影到一个项目节点，并保留每条任务的原 `workspacePath` 用于打开、归档和 Git 操作。导航仍能在工作树 scope 中恢复会话；不会将任务搬入源项目的运行队列。项目名相同但 Git 归属不同的工作区保持分开。
3. **ACP 模式使用 Agent 宣告。** 临时发现会话读取 `modes` 或 `category=mode` 的选项；UI 只显示这些原生 ID。首轮创建后、prompt 前调用对应 ACP 设置方法并检查 Agent 回包确认；不支持的 Agent 显示不可设置。该选择属于新会话草稿，权限请求仍逐次走 `session/request_permission`。
4. **ACP 终态与计时由投影单源计算。** 对 `refusal`、已知失败元数据和顶层错误统一投影失败状态及 `lastError`。思考段在首个正文、工具或计划更新时结束，记录耗时；转录重放使用已记录事件时间而非重放时钟。转录仍保存 Agent 原始结果，不修改其协议事实。
5. **创建前获取上游使用 Git 服务。** 设置默认为开启，选中本地分支若配置上游，则先非交互式 fetch 更新跟踪引用，比较本地与上游提交的祖先关系，从较新提交创建 detached 工作树；双方分叉时失败，不移动源分支。托管工作树标记记录创建时的提交与获取结果，供运行中会话的折叠信息块读取；工作树删除后该块不再可读，不作为会话内容或任务身份。

## Risks / Trade-offs

- [ACP mode 不是通用沙箱权限] → UI 显示 Agent 自报名称和说明，仅承诺 Agent 接纳的模式。
- [源项目路径已不存在或旧工作树缺少可核验标记] → 保留运行路径和独立会话记录，不猜测归属。
- [模式在草稿发现和正式创建之间变化] → 创建时重新校验，失败则不发送首轮输入。
- [第三方 `_meta` 包含敏感详情] → 只抽取受控长度的可读错误，并不输出原始请求标识或完整元数据。

## Migration Plan

新增元数据字段按缺省运行路径读取旧任务。可核验的现存托管工作树在项目视图读取时归并；不能核验的保持现状。无数据库主键迁移。回滚时旧版本忽略新增字段，运行路径和会话记录不变。
